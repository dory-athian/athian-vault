Cross-domain mechanisms — ranked by confidence
Air traffic control — the strip board
ACTIVE.md as the canonical sector state
session-continuity reasoned:

/Athian/docs/ACTIVE.md is the strip board: a flat, always-current inventory of every in-progress artifact. One entry per item, with a state snapshot — repos it touches, what happens next, who owns it, link to the artifact. The session discipline is simple and non-negotiable: open a session → read ACTIVE.md first; close a session → update the relevant entries before anything else. An item not on the strip board is considered landed (move to DECISIONS.md or a Linear issue) or abandoned — there is no implicit "I'll remember this."

ATC controllers don't track aircraft in memory. If it's not on the strip board, it doesn't exist as live work. The same logic clears the fog of "what was I doing?" without requiring any new tooling — just a file and a commitment that its emptiness means something.

Where it lives
/Athian/docs/ACTIVE.md — in the workspace git spine. One file, team-readable.
Relationship to prior ideas
Additive to DECISIONS.md. That tracks history; this tracks current state. Both are necessary.
"So if it's not in ACTIVE.md, we're agreeing it doesn't exist as live work."
Emergency medicine — bedside handoff
The active-plan stub at the site of the work
session-continuity external:

At session close, write a short structured stub — not a summary, a handoff note — directly inside the repo directory where active work happened. The file lives at .claude/handoff.md in whichever repo the session touched. It follows a fixed four-field SBAR template: Situation (what problem was being solved), Background (which files and decisions are load-bearing), Assessment (what's unresolved and why), Recommendation (exactly what the next session should do first). The stub is committed to the branch and travels with the work.

At session start, the opening ritual is to read any .claude/handoff.md files in the repos being opened, then supersede them as the session produces its own work. ER handoff happens at the bedside — not in a conference room — because context lives at the site of care. A separate session log (DECISIONS.md) requires you to remember to check it. This is impossible to miss because it's in the repo you opened.

Where it lives
.claude/handoff.md in the active repo. Committed to the branch. Ephemeral — deleted or superseded at next session open.
Relationship to prior ideas
Additive to DECISIONS.md (permanent ledger). This is a disposable re-entry card — used once, then superseded. Complements ACTIVE.md: that's workspace-level; this is branch-level.
"So it's like a sticky note on the file itself — I'd see it the moment I opened the branch."
Hollywood production — continuity polaroid
Session polaroid protocol
session-continuity reasoned:

At the close of every CE session, write a standardized 5-field snapshot file to /Athian/.sessions/YYYY-MM-DD-HHMMSS.polaroid.yaml. Fields: last_artifact (path), repos_touched (list), open_threads (list), next_action (one sentence, imperative), blocking_on (nullable). Commit it immediately. Polaroids are never edited — if state changes, a new polaroid supersedes the old one.

At session open, the skill reads the most recent polaroid and surfaces a one-paragraph resumption brief before any work begins. Film continuity supervisors take a polaroid of each scene's exact state — not a narrative description, a reconstruction artifact — so any crew member can reset the scene on any shooting day. The polaroid isn't documentation, it's state reconstruction.

Where it lives
/Athian/.sessions/ — in the workspace spine. One YAML file per session close. Append-only, never edited.
Relationship to prior ideas
Complements A (branch-level re-entry). This is workspace-level orientation; A is repo-level. Together they cover both entry points without duplicating each other.
"Oh, so it's like a git stash but for your brain state, not your code state."
Urban planning — lead agency designation
Cross-repo plan ownership via lead_repo:
discoverability reasoned:

Every plan that touches more than one repo carries a lead_repo: field in its YAML frontmatter — the single repo where the canonical copy lives and where changes must originate. Other touched repos carry a see_also: pointer back to the lead. A lightweight coordination file at /Athian/docs/COORDINATION.md lists every active cross-repo plan, its lead repo, and its current lifecycle state (draft / active / landed).

The prior plan manifest idea (prior survivor #3) establishes which repos a plan touches. This closes the harder question: where does the truth live when copies diverge, and who has authority to change it? A California highway crossing three counties is managed by the State DOT — it has authority over the boundary even though counties own the interior. No single county can reroute it unilaterally.

Where it lives
lead_repo: field in plan frontmatter. COORDINATION.md at /Athian/docs/ for the overview inventory.
Relationship to prior ideas
Extends prior survivor #3 (cross-repo manifest with repos: field). That names the repos; this designates authority among them. They compose, not compete.
"So platform can't just update that plan on its own — it has to go through wherever the lead is."
Urban planning — public comment period
Mandatory PR checkpoint before Linear promotion
artifact-lifecycle reasoned:

Before any planning artifact transitions into a formal Linear issue, it enters a brief "comment period" — a PR opened against the /Athian repo with the artifact as the diff. The PR template prompts reviewers for one of three responses: approve, request revision, or mark as blocked by another item. Only after merge does the n8n automation fire and create the Linear issue.

Prior survivor #7 wires plan frontmatter to auto-create Linear issues. Without this checkpoint, that automation fires on half-baked plans and creates backlog noise that kills trust in the system over time. Urban planning requires a public comment period before a plan can be adopted — not to slow things down, but because the plan must be surfaced before it becomes binding. The PR is posted outside the county planning office; someone has to have had a chance to see it. The 48-hour window is a starting point, not a constraint — the team should decide the right window for their cadence.

Where it lives
PR against /Athian repo. Template lives in .github/PULL_REQUEST_TEMPLATE/plan-promotion.md.
Relationship to prior ideas
Additive to prior survivor #7 (n8n → Linear wiring). That automates the promotion; this adds the human gate before it fires. Both are necessary.
"So nothing hits the backlog that at least one other person didn't have a chance to see."

Coverage Sheet per Artifact (*.coverage.yaml) Sidecar file discipline proportionate to a 40-person org running structured change management. At 8 people, the handoff stub + ACTIVE.md answer the same question.
Traffic Management Initiative (TMI: flag) A good team norm turned into a file format. At 8 people, overload is visible without a formal flag. The norm belongs in standup, not in ACTIVE.md's schema.
